# GitHub Pages

Публичный сайт: https://m0rg0t.github.io/cardputer-oracle/. В репозитории включён источник GitHub Actions; обновление запускается вручную через Deploy GitHub Pages.

Исходники — site/index.html, site/style.css, site/language.js и site/locales/{en,ru,zh}.json. Генератор tools/build_site.py использует стандартную библиотеку Python 3.10+. Для каждого языка примеры берутся из соответствующей настоящей колоды, включая три готовых WAV. Всего на сайте девять записей.

~~~sh
python tools/build_site.py
python -m http.server 8765 --bind 127.0.0.1 --directory build/site
~~~

Открыть http://127.0.0.1:8765/. При изменениях повторить build_site.py. Для ссылки на репозиторий передать --repository OWNER/REPOSITORY.

Генератор проверяет локальные ссылки всех страниц. На выходе 32 публичных файла, включая три инструкции установки; приватный конфиг, папка SD целиком, журналы и прошивки не копируются. Единственный JavaScript отвечает за язык; трекеров, внешних шрифтов и API нет. Аудио включается посетителем.

## Языки и снимки экрана

- /en/, /ru/ и /zh/ — самостоятельные статические страницы с английским, русским и упрощённым китайским текстом. Их можно отправлять прямой ссылкой.
- Корневая страница определяет язык по navigator.languages: сначала сохранённый ручной выбор, затем первый поддерживаемый язык браузера, иначе английский. Региональные варианты ru-RU и zh-CN распознаются; все zh-варианты ведут к упрощённому китайскому.
- Переключатель English / Русский / 简体中文 запоминает выбор в localStorage и сохраняет текущий раздел. Прямая языковая ссылка имеет приоритет над сохранённым выбором и не перенаправляется.
- При отключённом JavaScript корень показывает английскую страницу; переключатель остаётся обычными рабочими ссылками. Заблокированный localStorage не мешает навигации.
- Каждая страница использует свои примеры текста, WAV, инструкцию, снимки главного экрана и результата, а также чек. Проверяются язык и актуальность озвучки.
- Снимки и чеки для сайта находятся в docs/media/. Их версия и SHA-256 записаны в site-media.json. После изменения интерфейса обновите эти файлы снимками симулятора соответствующей сборки. Чек берётся из build/previews/{language}/tea_last_cookie.png после генерации ресурсов. Не переводите надписи поверх чужого скриншота.

Проверки: `python -m unittest discover -s tools -p test_site.py` и `node tools/test_site_language.cjs`. Node нужен только для проверки поведения языка, сборка сайта остаётся на стандартной библиотеке Python. Относительные ссылки и перенаправления сохраняют префикс репозитория в GitHub Pages.

## Публикация

1. Создать репозиторий GitHub и отправить локальную main.
2. Settings → Pages → Source → GitHub Actions.
3. Actions → Deploy GitHub Pages → Run workflow.
4. Дождаться build и deploy. URL появится у environment github-pages.

Публикация только через workflow_dispatch. Checks на push / pull request проверяют сайт без развёртывания. Все пути относительные и подходят для OWNER.github.io/REPOSITORY/.

Имя текущего репозитория передаётся генератору через переменную окружения. Deploy job получает pages: write и id-token: write. API-ключи OpenAI, LiteLLM и ElevenLabs в GitHub Secrets для сайта не нужны.

[Официальная документация workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
