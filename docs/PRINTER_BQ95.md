# BQ95 / FunPrint

Используется детская камера с термопринтером. Во время подключения на ней должен быть открыт экран FunPrint с QR-кодом; автовыключение лучше отключить.

## Управление

Одна автоматическая попытка при раскрытии прогноза. P на экране результата повторяет поиск или печатает копию. Одновременно передаётся один зафиксированный чек. Сеть и телефон для печати не нужны.

После отправки статус «Чек передан» подтверждает передачу данных и ответ камеры, но не наличие бумаги. При обрыве частичный чек не повторяется автоматически.

## Проверенный профиль

- Имя: BQ95.
- Идентификация текущего экземпляра: адрес 13:03:af:12:18:19 либо совпадающие manufacturer data.
- Сервис AE30; AE01 write without response; AE02/AE04 notify.
- Ширина 384 точки; изображение 336 точек, поля по 24.
- Растр: black=1, младший бит первым, 48 байт на строку.
- Передача: блоки не более 63 байт и MTU−3, интервал 12 мс.
- Ответ A3: для этого BQ95 принимаются 00 и 04. Значение 04 не трактуется как перегрев универсально.
- Поиск ограничен тремя секундами, подключение шестью, передача — общим таймаутом.

Основание профиля: [TiMini Print](https://github.com/Dejniel/TiMini-Print). Полный чек с крупной картинкой физически напечатан с Mac и подтверждён пользователем; переход транспорта на Cardputer проверяется отдельно.

Для другой камеры изменить фильтр в firmware/src/bq95_printer.cpp после исследования GATT. Соседние неизвестные принтеры автоматически не выбираются.

## Формат ORP1

Заголовок 20 байт: magic ORP1, u16 width, u16 height, u32 raster length, u32 raster CRC32, u32 content CRC32. Числа little-endian; затем 48 байт на строку, максимум 1024 строки.

Content CRC связывает чек с заголовком, текстом и картинкой. Для Таро также фиксируются вопрос и выбранные карты. SD читает основная задача; BLE получает отдельный RAM-буфер.

## M5Apps / NVS

В 0.5.1 предварительная проверка NVS останавливала печать до поиска камеры. M5Apps использует apps_nvs, тогда как NimBLE 1.4.3 требовала стандартный nvs.

С 0.5.2 tools/nimble_m5apps.py компилирует отдельную копию NimBLEDevice.cpp без обязательной инициализации/стирания NVS. MYNEWT_VAL_BLE_STORE_CONFIG_PERSIST=0 оставляет данные Bluetooth в RAM. Контроллер и host инициализируются штатно; разделы загрузчика не меняются.

Проверка tools/check_nimble_storage.py анализирует скомпилированную библиотеку: нет NVS-зависимостей, persistent storage пуст, запуск контроллера и host сохранён.

Источники: [разметка M5Apps](https://github.com/d4rkmen/M5Apps#partition-layout), [радиокалибровка ESP-IDF 4.4.7](https://github.com/espressif/esp-idf/blob/v4.4.7/components/esp_phy/src/phy_init.c).

## Инструменты для исследования с компьютера

tools/probe_printer.py и tools/test_print_bq95.py используют bleak; установить его отдельно. tools/print_prediction.py проверяет подготовленный чек. Прочитайте --help и код перед --send: этот флаг физически запускает печать.

Диагностические JSON, захваты и история отправок сохраняются локально и не коммитятся.
