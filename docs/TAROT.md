# Таро через LiteLLM — 0.6.0

Четвёртая тема использует HTTPS к существующему LiteLLM. Отдельный Go-сервис не требуется. Вводится вопрос до 80 символов или нажимается Enter для общего расклада. Tab переключает русские и английские буквы, Shift — регистр, Backspace удаляет последний символ, Esc возвращает на главный экран. Затем устройство случайно выбирает три разные карты из 22 старших арканов: прошлое, настоящее, будущее. Модель получает эти карты и вопрос; результат фиксируется до следующего расклада.

На экране доступны обычная прокрутка и P для печати. На чеке крупное изображение трёх карт почти на всю ширину, их названия, вопрос и толкование. Повтор P печатает тот же результат без нового API-запроса. Для Таро пока есть текст, рисунок, эффекты и печать; динамической озвучки нет. Прежние три темы сохраняют 120 готовых озвучек на SD.

Язык названий карт, вопроса по умолчанию, толкования и чека определяется сборкой: EN по умолчанию, RU через --language ru, упрощённый китайский через --language zh. Tab меняет только раскладку ввода. Запрос модели не привязан к докладу или месту использования.

## Настройка

В SD `/ORACLE/config.json` находится приватный конфиг. Пример без секретов есть в `config.example.json`. `wifi` — от одной до четырёх известных сетей в порядке предпочтения. Устройство ищет их при запуске Таро, начиная с первой доступной; после видимых пробует остальные сохранённые сети, включая скрытые. Для точки доступа iPhone включите «Максимальная совместимость» и держите открытым экран режима модема во время первого подключения.

`tarot.host` — имя HTTPS-сервера LiteLLM без `https://`, порта и пути. Запрос идёт на `/v1/responses`. `tarot.model` — точное имя модели в LiteLLM; проверена `openai/gpt-5.6-luna`. `tarot.token` — виртуальный ключ LiteLLM. Исходный ключ OpenAI остаётся в настройках прокси. Реальный `config.json` не включается в ZIP, исходники или BIN и записывается на карту отдельно. При обновлении сохраняйте его.

Для HTTPS нужны `/ORACLE/tls/roots.pem` и корректное время. Устройство сверяет время через NTP, проверяет сертификат и имя сервера; проверки TLS не отключаются. В комплекте официальные [ISRG Root X1](https://letsencrypt.org/certs/isrgrootx1.pem) и [ISRG Root X2](https://letsencrypt.org/certs/isrg-root-x2.pem). Если ваш сервер использует другую цепочку, добавьте соответствующий проверенный корневой сертификат в этот файл.

VPN iPhone обычно не передаётся клиентам его точки доступа. В этой схеме телефон нужен только для доступа к LiteLLM; доступ к OpenAI обеспечивает уже сам прокси.

## Поведение при ошибках

Wi-Fi включается только для Таро. Перед HTTPS освобождаются изображение предыдущей карточки и простаивающий BLE-стек; после запроса Wi-Fi выключается, затем при необходимости запускается печать. Во время передачи чека новый сетевой запрос не начинается. Esc отменяет ожидание; уже отправленный запрос может завершиться у провайдера, но его поздний результат не заменяет экран и не печатается. Новая попытка возможна после завершения предыдущей.

На одно подтверждение вопроса прошивка делает один POST и не повторяет его автоматически при тайм-ауте. Настройки повторов и маршрутизации самого LiteLLM определяются конфигурацией сервера. Ошибка сети, токена, лимита или неполный ответ выводятся на экран; после Esc можно использовать автономные темы. Максимальный ответ ограничен 16 КБ, текст проверяется на формат, длину и поддерживаемые символы.

## Проверка

Пробный реальный запрос от кода прошивки к `openai/gpt-5.6-luna` через LiteLLM вернул HTTP 200 за 4,71 с: 326 входных и 71 выходной токен. Для короткого ответа используется `reasoning.effort=none`, лимит 512 выходных токенов и строгая JSON-схема. Ответ успешно прочитан тем же C++-парсером. TLS прокси проверен с комплектными корнями. Эти проверки выполнены на Mac. Подключение конкретного Cardputer к точке доступа, переход BLE → Wi-Fi → BLE и физическая печать Таро требуют проверки на устройстве после установки.

Формат API сверялся с официальными [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и [LiteLLM Responses API](https://docs.litellm.ai/docs/response_api).
